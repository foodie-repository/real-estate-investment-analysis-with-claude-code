# 2부 7장. 거래량 지도

이 프로젝트는 매매·전세·월세 실거래가를 단지별로 집계하고, 거래량 또는 세대수 대비 회전율 순위를 지도와 표로 보여주는 Streamlit 대시보드 예제입니다. 지역, 거래유형, 기간, 면적 조건을 바꿔 거래가 집중된 단지를 비교할 수 있습니다.

## 책과 프롬프트 대응

- 책: 『감을 확신으로 바꾸는 AI 부동산 투자』 2부 7장
- 프롬프트: [2부 7장 거래량 지도 대시보드 프롬프트](../../prompts/part02/chapter07/01_trade_map_dashboard.md)

## 파일 구조

```text
part07_trade_map/
├── dashboard/
│   ├── app.py           # Streamlit 화면과 필터
│   ├── constants.py     # 지도와 화면 설정
│   ├── db.py            # DuckDB 연결
│   ├── preprocessing.py # 거래 데이터 전처리
│   ├── pivot.py         # 거래량·회전율 집계
│   └── map_builder.py   # Folium 지도 생성
└── notebooks/
    ├── 01_eda.ipynb
    ├── 02_preprocessing.ipynb
    └── 03_map_prototype.ipynb
```

## 실행 전 준비

저장소 루트에서 의존성과 환경변수를 준비합니다.

```bash
uv sync
cp .env.example .env
```

실거래가, 공동주택 세대수, 좌표 데이터가 같은 지역과 기간을 대상으로 DuckDB에 준비되어 있어야 합니다. 좌표나 세대수 연결이 되지 않는 단지는 집계 결과에는 포함되더라도 지도 마커 또는 회전율 계산에서 제외될 수 있습니다.

지도 타일을 사용하려면 `.env`에 V-World API 키를 설정합니다.

```dotenv
VWORLD_API_KEY=발급받은_API_키
```

## 실행

```bash
uv run streamlit run projects/part07_trade_map/dashboard/app.py
```

화면의 사이드바에서 거래유형과 랭킹 기준을 선택하고, 시도·시군구·읍면동·기간·면적 조건을 설정합니다. 결과 지도와 랭킹 표를 함께 보면서 거래량과 회전율 순위가 어떻게 달라지는지 비교할 수 있습니다.

## 노트북

`notebooks/01_eda.ipynb`는 원자료를 확인하고, `02_preprocessing.ipynb`는 주소·면적·연식과 거래 데이터를 정리하며, `03_map_prototype.ipynb`는 지도 표시 전 단계의 결과를 확인합니다. 데이터베이스가 없는 상태에서는 노트북 일부가 실행되지 않을 수 있습니다.

## 해석할 때 주의할 점

- 거래량은 거래가 많이 발생한 정도를 보여주며, 가격 상승이나 투자수익을 직접 의미하지 않습니다.
- 회전율은 세대수 연결 상태와 거래 집계 조건의 영향을 받습니다.
- 최신 연도나 최신 월이 완결되지 않았다면 완결된 기간과 직접 비교하지 마세요.
- 지도 마커 누락은 코드 오류가 아니라 주소·좌표 매칭 문제일 수 있으므로 연결률을 먼저 확인하세요.
- 교통·입주·상권과 같은 거래량 변화의 원인은 별도 자료와 출처를 사용해 검증해야 합니다.
